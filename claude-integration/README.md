# Интеграция kinematic-cad с Claude Code

Три механизма, они независимы — ставьте те, что нужны.

## 1. Слэш-команды (явный вызов через `/`)

```bash
mkdir -p .claude/commands            # проектные, коммитятся в репозиторий
cp claude-integration/commands/*.md .claude/commands/
# либо личные, доступные во всех проектах:
cp claude-integration/commands/*.md ~/.claude/commands/
```

Имя файла = имя команды. Появятся:

| Команда | Что делает |
|---|---|
| `/kcad <задача>` | полный цикл inspect → правка спеки → build → check → golden |
| `/kcad-check [--smoke]` | пересборка + инварианты, с разбором падений |
| `/kcad-diff` | golden-дифф против эталона с объяснением каждого числа |
| `/kcad-new <описание машины>` | скаффолдинг проекта и заполнение спеки |

Команды с `!`-строками (`kcad-check`, `kcad-diff`) выполняют bash ДО начала ответа,
так что Claude видит свежий вывод проверок сразу, без лишнего круга.

## 2. Самозапуск (без `/`)

Скилл триггерится своим `description`. Он уже написан «пушисто» — перечисляет и
инструменты (Isaac Sim, Omniverse, USD, prim, articulation), и симптомы («правка одного
узла сломала остальное», «оси и начала координат неверны»). Чтобы срабатывало надёжнее
именно на вашей лексике, допишите в `description` в `SKILL.md` свои слова: названия узлов
(«каретка», «дивертор», «накопитель»), имя проекта, «трек 3», что угодно, чем вы реально
называете задачу в чате.

Скиллы срабатывают на содержательных многошаговых запросах и обычно НЕ срабатывают на
однострочных вроде «покажи файл» — это нормально и лечится явным `/kcad`.

## 3. Хук: авто-проверка после правки спеки

Самый сильный вариант — проверки запускаются машиной, а не по доброй воле модели.
Скопируйте содержимое `hooks/settings.example.json` в `.claude/settings.json` проекта
(или слейте с существующим). После каждой правки `machine.yaml` автоматически пойдёт
пересборка и прогон инвариантов, и Claude увидит падение сразу же.

## 4. Дисциплина через CLAUDE.md

```markdown
Работа со сценой Isaac Sim — только через скилл kinematic-cad.
Правки идут в spec/machine.yaml, стейдж руками не редактируем.
После каждой правки: kcad build && kcad check && kcad golden --strict.
Упавший инвариант чиним в спеке, а не ослаблением проверки.
```

---

Детали синтаксиса слэш-команд и хуков (фронтматтер, `$ARGUMENTS`, `$1`, `!`-выполнение,
`@`-ссылки на файлы, набор событий хуков) периодически меняются — сверяйтесь с
https://docs.claude.com/en/docs/claude-code/overview
